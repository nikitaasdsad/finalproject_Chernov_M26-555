\## Описание проекта



\*\*ValutaTrade Hub\*\* — консольное приложение на Python для управления валютным портфелем пользователя.



Приложение позволяет регистрировать пользователей, выполнять авторизацию, просматривать валютный портфель, покупать и продавать валюту, получать актуальные курсы валют и обновлять их из внешних API.



Проект поддерживает работу с фиатными и криптовалютами.



\### Основные возможности



\- Регистрация новых пользователей.

\- Авторизация по логину и паролю.

\- Хранение пользовательских данных в JSON-файлах.

\- Просмотр баланса валютного портфеля.

\- Покупка и продажа валют.

\- Получение курса одной валюты относительно другой.

\- Просмотр списка доступных курсов.

\- Обновление курсов через внешние API.

\- Получение курсов фиатных валют и криптовалют.

\- Кэширование полученных курсов.

\- Хранение истории обновлений курсов.

\- Автоматическое обновление курсов через Parser Service.

\- Логирование действий приложения и ошибок.

\### Назначение основных модулей



\- `cli/` — командный интерфейс приложения.

\## Настройка API-ключа

Для получения курсов фиатных валют используется ExchangeRate-API.

API-ключ необходимо получить на сайте:

https://www.exchangerate-api.com/

Ключ хранится в переменной окружения `EXCHANGE\_RATE\_API\_KEY`.

Для текущего окна PowerShell задайте переменную:



```powershell

$env:EXCHANGE\_RATE\_API\_KEY = "ВАШ\_API\_КЛЮЧ"

```



Чтобы сохранить переменную окружения для последующих запусков Windows:



```powershell

setx EXCHANGE\_RATE\_API\_KEY "ВАШ\_API\_КЛЮЧ"

```

После выполнения `setx` необходимо открыть новое окно PowerShell.

\## Parser Service



Parser Service отвечает за получение актуальных курсов валют из внешних источников.



В проекте используются два источника данных:



\- \*\*ExchangeRate-API\*\* — курсы фиатных валют: USD, EUR, GBP, RUB.

\- \*\*CoinGecko API\*\* — курсы криптовалют: BTC, ETH, SOL.



Основная логика Parser Service находится в каталоге `valutatrade\_hub/parser\_service/`.



Назначение модулей:



\- `config.py` — настройки API, валют, путей к файлам и интервалов обновления.

\- `api\_clients.py` — клиенты для обращения к внешним API.

\- `updater.py` — получение и объединение курсов из разных источников.

\- `storage.py` — сохранение истории и обновление кэша.

\- `scheduler.py` — автоматический запуск обновлений по расписанию.



\### Как включить Parser Service



Сначала настройте API-ключ и запустите приложение:



```powershell

uv run python main.py

```



В интерфейсе выполните команду:



```text

update-rates

```



Она запускает обновление курсов из доступных источников.



Для запуска автоматического обновления используйте:



```text

scheduler

```



Интервал обновления задаётся в конфигурации Parser Service параметром `update\_interval\_seconds`. По умолчанию используется 300 секунд.



\## Кэширование курсов и TTL



Полученные курсы сохраняются в файле:



```text

data/rates.json

```



Кэш позволяет использовать ранее полученные курсы без постоянных обращений к внешним API.



Для кэша используется параметр TTL (Time To Live) — время, в течение которого сохранённые данные считаются актуальными.



В проекте стандартное значение TTL составляет:



```text

300 секунд (5 минут)

```



После истечения TTL приложение должно обновить курсы, прежде чем использовать устаревшие данные для операций, требующих актуального курса.



Время последнего обновления хранится в кэше в поле `last\_refresh`.



История полученных курсов сохраняется отдельно:



```text

data/exchange\_rates.json

```



Таким образом:



\- `rates.json` — текущий кэш курсов.

\- `exchange\_rates.json` — история обновлений курсов.



\## Хранение данных



Приложение использует JSON-файлы:



| Файл | Назначение |

|---|---|

| `users.json` | Данные зарегистрированных пользователей |

| `portfolios.json` | Валютные портфели пользователей |

| `rates.json` | Текущий кэш курсов |

| `exchange\_rates.json` | История обновлений курсов |



Пароли пользователей хранятся в виде хешей с солью, а не в открытом виде.



Для записи JSON-файлов используется механизм безопасного обновления через временный файл.



\## Логирование



Действия приложения и ошибки записываются в файл:



```text

logs/actions.log

```



Для логирования используется стандартный модуль `logging`.



Настроена ротация логов: при достижении заданного размера старые файлы логов сохраняются в резервных копиях.
